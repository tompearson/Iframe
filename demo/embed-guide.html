Designer handout — embed your client’s AI assistant (examples use a fictitious brand)

Embed guide for web designers

Add your client’s AI site chat with an iframe. Examples use the fictitious brand Horizon Movement Co. — swap in your client’s name, domains, and styles. You do not need API keys or backend access.

Not for production copy-paste: the /float page on this host is QA only (floating launcher, internal test questions). Build a layout that matches the client and embed only /embed/.
Embed only — not AI data: this guide covers the iframe and client-site branding. It does not cover how answers or Sources are chosen (website crawl, search index, models, prompts). That is usually separate AI engineering by the project’s technical team — unless you provide that work yourself, or the client has contracted the same development team for both the embed and the assistant backend (define that in your scope of work). Otherwise, report wrong answers or wrong Sources to the project owner, not as a web-design fix.

What to get from the project owner

  • Widget URL — e.g. https://chat.horizonmovement.example/embed/
  • Client domain allowlist — e.g. https://www.horizonmovement.example (www, apex, staging)
  • Brand strings — iframe title and section labels (client name, not the host vendor)
  • No secrets — never paste API keys or Bearer tokens into the client site

Basic inline embed

Replace EMBED_HOST and Horizon Movement Co. with your client.

<section class="horizon-assistant" aria-label="Ask Horizon Movement Co.">
  <iframe
    src="https://EMBED_HOST/embed/"
    title="Horizon Movement Co. site assistant"
    width="100%"
    height="560"
    style="border:0;max-width:440px;display:block;"
    loading="lazy"
  ></iframe>
</section>

Squarespace / CMS

Use a Code or HTML block, paste the iframe, publish, and test the live client URL. If the frame is empty, ask the owner to allowlist the client domain and check the browser console for CSP errors.

Floating chat

Build your own launcher copy and styling for the client; point the iframe at /embed/ only. Do not reuse the internal QA chrome from /float.

Testing checklist

  • Chat loads on the client’s published URL (mobile and desktop)
  • Page chrome matches the client brand; iframe title uses the client name
  • Questions return answers (whether they are correct is AI engineering, not this embed)
  • Sources links are clickable if shown (which URLs appear is also AI engineering)
  • No secrets in page source or Network tab

Blank iframe?

Usually the client domain is not on the embed host’s frame-ancestors list. Send the owner the exact origin (e.g. https://www.horizonmovement.example) and retest after deploy.
